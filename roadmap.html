The organizing principle

One brain, many bodies

The simulation is built once, as an engine-agnostic core that knows nothing about rendering, Unreal, or 2D. Every game — the throwaway 2D fun-test now, the UE5 world later — is just a body that speaks to the same brain through one fixed interface. That's what makes it plug-and-play. It also means the 2D game is never wasted work: it's the test harness for the exact core Unreal will run.

Rule 01
One core, one truth

The Python model stays the reference & balancing oracle forever; the C++ core is the shipping version. Automated golden tests keep them identical — never two implementations drifting apart.

Rule 02
The wall

Every action — player or NPC — passes through the measured Intent interface the Accountant observes. Nothing reaches in and mutates state directly. It's what keeps contribution honest and lets the game double as a research testbed.

Rule 03
LLM only at the edges

Language models render dialogue and propose world-changes — nothing more. Never in the tick loop, never load-bearing state. The deterministic sim is always the fact-checker.

The path

Seven phases, gated — not rushed

Each phase has one job and one gate that must pass before the next begins. We take as long as each needs. The pivotal ordering: fun is proven in 2D before the C++ core is ever written — because the model is already Python, the cheapest possible fun-test is a 2D game on it, and we only pay for the plug-and-play core once the design has earned it.

The contract

What “plug into UE5” actually means

The interface SimCore exposes — the same one the 2D game and Unreal both speak. Your game never sees the core's internals; only this.

// init
SimCore(config, seed)

// drive — the ONLY way to affect the world
submitIntent(agentId, intent)     // Gather · Trade · Build · Move · Speak(claim) …

// tick — deterministic
step(dt)

// read
snapshot()        → render state
drainEvents()     → what happened this tick (trade cleared, belief shifted,
                      contribution paid, shortage, rumour spread …)
query(...)        → score · an agent's beliefs (for dialogue) · market state

// persist
serialize() / load()

// edges — async, outside the tick, always validated first
proposeWorldChange(ctx)   renderDialogue(belief, prompt)

// on the UE5 side
USimWorldSubsystem owns + ticks the core · Blueprint nodes for intents/queries
                   · dispatches events · maps AActor ⇆ agentId
